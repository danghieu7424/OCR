## 2026-11-17 follow-up: cross-process reader/checkpoint

The pager now holds a process-wide shared OS lock while any reader remains
open. Checkpointing serializes on the WAL lock, briefly upgrades the database
file lock, and reports `CheckpointOutcome::Deferred` if another process still
holds a reader. Local snapshots continue to use `min_reader_frame`; a local
registry read/write lock keeps page reads out of the checkpoint write window.
Windows lock conflicts (`ERROR_LOCK_VIOLATION`) are normalized to
`VfsError::LockBusy`.

Verification on the Windows host:

```text
cargo fmt --all -- --check
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo audit
cargo metadata --locked --no-deps --format-version 1
git diff --check
```

Result: 88 unit/integration tests and one doctest passed; strict Clippy passed;
`cargo audit` scanned 93 dependencies without failing.

The current 5,000-row/20-open benchmark ran three times. Median open times were
1,099–1,157 us for checkpointed files and 1,919–2,000 us with WAL. The
median-of-run medians was 1,122 us and 1,927 us respectively. The earlier
single-run reference above was 1,005 us and 1,876 us; these are small host
measurements, not a performance guarantee.

Android validation:

```text
cargo ndk -t armeabi-v7a -P 23 check --workspace --all-targets --locked
cargo ndk -t arm64-v8a -P 23 check --workspace --all-targets --locked
cargo ndk -t armeabi-v7a -P 23 test -p ferrite-pager --lib checkpoint_defers_for_reader_in_another_process --no-run --locked
```

Both Android workspace cross-checks passed. The pager test binary was run on
the connected SM-J250F as shell in `/data/local/tmp`; all 30 pager tests passed,
including the subprocess test that holds a reader open while another process
attempts checkpoint. The temporary test binary was removed. The linker
continued to warn `DT_FLAGS_1=0x8000001`; hardening flags remain enabled.

This still does not validate WBF's app-private sandbox or a physical power cut.
The test exercises simulated torn writes and an Android shell-accessible
directory, not loss of device power. Remote GitHub Actions remains unverified:
the configured Actions API responds 404.
